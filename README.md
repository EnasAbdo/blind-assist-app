# تطبيق مساعدة المكفوفين (Blind Assist App)

تطبيق بايثون (Kivy) لموبايل أندرويد، بيساعد شخص كفيف يكشف على محيطه
بالصوت عن طريق كاميرا الموبايل، Real-time.

## آلية الاستخدام
ما في أزرار صغيرة لازم تدور عليها — النظام كله عن طريق نقرات بأي
مكان بالشاشة:

| عدد النقرات | الوظيفة | الحالة |
|---|---|---|
| نقرة واحدة | كشف الأجسام والعوائق | ✅ شغال |
| نقرتين | كشف العملات | 🔜 قريباً |
| ثلاث نقرات | التعرف على السيارات | 🔜 قريباً |

## هيكل المشروع
```
blind_assist_app/
├── main.py              # التطبيق (واجهة Kivy + نظام النقرات + شاشة الكاميرا)
├── detector.py           # تشغيل موديل الكشف (ONNX عبر OpenCV)
├── tts_helper.py         # تحويل النص لكلام
├── export_to_onnx.py     # سكريبت تصدير best.pt إلى ONNX
├── requirements.txt
├── buildozer.spec        # إعدادات تغليف APK لأندرويد
└── models/
    ├── object_detection.onnx   # ⚠️ لازم تحطه انت (مش موجود حالياً)
    └── labels.txt               # ⚠️ ملف تجريبي - استبدله بأصناف موديلك
```

## خطوة 1: تصدير الموديل من Colab
بعد ما تخلص تدريب YOLOv8m على Colab، شغّل هالأمر (على جهازك أو بنفس Colab):

```bash
pip install ultralytics
python export_to_onnx.py --model best.pt --imgsz 320
```

- رح يطلعلك ملف `best.onnx` + قائمة بأسماء الأصناف بالترتيب.
- انسخ `best.onnx` إلى `models/object_detection.onnx`
- افتح `models/labels.txt` واستبدل المحتوى التجريبي بأسماء أصنافك
  **بنفس الترتيب** يلي طلع معك.

> ملاحظة: استخدمنا `imgsz=320` بدل 640 عشان نضمن سرعة Real-time
> على الموبايل. إذا حسيت الدقة ضعيفة، جرب 416. كل ما زاد الرقم،
> صار الكشف أبطأ.

## خطوة 2: التجربة على الكمبيوتر (قبل ما تبني APK)
أسهل وأسرع طريقة تتأكد كل شي شغال قبل ما تضيع وقت بالتغليف:

```bash
pip install -r requirements.txt
python main.py
```

هيك بتفتح نافذة كمبيوتر عادية، بتقدر تجرب النقرات وتشوف الكاميرا
وتسمع الصوت وين ما كان في مشكلة، وتصلحها قبل تجربتها عالموبايل.

## خطوة 3: بناء تطبيق أندرويد (APK)
```bash
pip install buildozer cython
buildozer -v android debug
```

الملف الناتج (`.apk`) رح يكون بمجلد `bin/`. انقله عالموبايل وثبّته
(لازم تفعّل "تثبيت من مصادر غير معروفة" بإعدادات الأندرويد).

**أول مرة بتبني رح تاخد وقت طويل** (ينزّل Android SDK/NDK كامل).
كمان لازم يكون عندك Linux (أو WSL على ويندوز) — Buildozer ما بيشتغل
مباشرة على ويندوز أو macOS بدون بيئة Linux.

## ليش استخدمنا ONNX + OpenCV بدل TFLite؟
جربنا نتجنب مشكلة معروفة: مكتبة `tflite-runtime` ما إلها دعم رسمي
موثوق مع أدوات تحويل بايثون لأندرويد زي Buildozer. بالمقابل،
`opencv-python` (يلي أصلاً مستخدمينه لفتح الكاميرا) عنده دعم كامل
ومضمون، وقادر يشغّل موديلات ONNX مباشرة عن طريق `cv2.dnn` بدون أي
مكتبات إضافية تعقّد عملية التغليف.

## إضافة الموديلين الجدد لاحقاً (العملات والسيارات)
البنية جاهزة لهيك — بس لما يجهز كل موديل:
1. صدّره لـ ONNX بنفس الطريقة (`export_to_onnx.py`)
2. حطه بـ `models/` باسم مختلف (مثلاً `currency_detection.onnx`)
3. بملف `main.py`، بدالة `set_model()` بصف `CameraScreen`، ضيف حالة
   جديدة تحمّل الموديل المناسب حسب `model_key`
4. بدالة `_process_taps()` بصف `HomeScreen`، بدّل استدعاء
   `tts.speak("...قيد التطوير")` باستدعاء `self._go_to_model("currency_detection")`

## ملاحظات مهمة للتجربة الحقيقية مع مستخدم كفيف
- الوقت الحالي بين إعادة الإعلان الصوتي عن نفس الجسم هو ~1.2 ثانية
  (`DETECTION_INTERVAL` بملف `main.py`) — جرّب تعدله حسب تجربتك.
- ينصح تضيف اهتزاز (haptic feedback) مع كل نقرة صحيحة عشان تأكيد
  إضافي غير الصوت (ممكن نضيفها لاحقاً عن طريق `plyer.vibrator`).
- لو حابب صوت أوضح وطبيعي بالعربي أكتر من TTS الافتراضي للجهاز،
  في خيارات لاحقة زي Google Cloud TTS أو ElevenLabs — بس هاي بتحتاج
  إنترنت واشتراك، عكس TTS الحالي يلي يشتغل بدون نت.
